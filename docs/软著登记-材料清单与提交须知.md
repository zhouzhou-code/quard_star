## 二、源程序 / 文档的格式硬性要求（CPCC）

**源程序：**
1. 每页不少于 **50 行**（程序结尾页除外）。
2. 每页须有 **软件名称 + 版本号**（页眉）与 **页码**。
3. 提交 **前 30 页 + 后 30 页**；若总页数 ≤ 60 页，则 **提交全部**。
4. 连续行号、字体清晰（一般用等宽字体，小五号/9pt 左右即可达到约 50 行/页）。

> 本软件自主源码约 **1988 行**，按 50 行/页约 **40 页（< 60 页）**，故 **全文提交**。
> `RV-Mailbox-V1.0-源程序提交稿.txt` 已按"页眉(软件名+版本+页码) + 50 行/页 + 换页符(\f)"
> 排好；导入 Word/记事本打印为 PDF 即满足分页与页眉要求（换页符 \f 会触发分页）。

**软件文档（说明书）：**
1. 同样 **前 30 页 + 后 30 页**（不足 60 页全提交）。
2. 每页含软件名称、版本号、页码。
3. **图文并茂**（本说明书含系统拓扑、时序图、寄存器手册表，符合要求）。
4. mermaid 图需先导出为图片再插入文档（见 §四）。

## 三、关于源代码的开源许可（提示，非阻碍）

本软件部分代码遵循 GPL 许可（QEMU 设备模型属 GPLv2、Linux 内核驱动 `MODULE_LICENSE("GPL")`）。
**软件著作权登记与开源许可并不冲突**：著作权登记确认的是"作者对该代码表达享有著作权"，
而 GPL 是著作权人对外授予的使用许可。以 GPL 发布并不丧失著作权，仍可正常登记。
登记时无需特别声明许可证；若申请表有"软件说明"可如实提及基于开源框架自主开发。

> **独立性定位（重要）**：本邮箱在寄存器编程范式上参考了 ARM MHU v1/v2 的设计思想，
> 但代码为自主编写，与 ARM MHU 源码/RTL 无复制衍生关系。说明书首页已含"自主开发声明"。

## 四、把说明书 mermaid 图转成图片 + 文档转 PDF/Word（操作建议）

本机暂无 pandoc / libreoffice。两种可选路径：

- **路径 A（推荐，零安装）**：用支持 Markdown+mermaid 的编辑器（Typora / VS Code + Markdown Preview Enhanced / 飞书文档）打开说明书，导出/打印为 PDF；mermaid 会自动渲染为图。
- **路径 B（命令行）**：安装 `pandoc` + `mermaid-filter`（或先用 `mmdc` 把图导出 PNG 再插入），再 `pandoc 说明书.md -o 说明书.pdf`。需联网装包（可走代理）。

转 PDF 后，在页眉加"RV-Mailbox V1.0"、页脚加页码即可。
